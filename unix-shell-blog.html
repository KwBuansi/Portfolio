Unix Shell Architecture

Davidson College · CSC 250 · Kwasi Buansi

A from-scratch command-line shell in C that parses user input into executable pipelines — supporting I/O redirection, background jobs, command history, and signal handling through POSIX system calls.

C POSIX Systems Programming
View project on GitHub

The goal

The assignment was to build a shell that behaves like a real Unix terminal — not a toy evaluator. That meant handling multi-stage pipelines, redirecting stdin/stdout to files, running jobs in the background, and recovering gracefully from signals like SIGINT and SIGTSTP.

How it works

Input moves through a tokenizer that splits commands into words, operators, and redirection tokens. A parser builds an abstract syntax tree of pipelines and simple commands. The executor walks that tree, calling fork() for each stage, wiring pipes with pipe() and dup2(), and waiting on child processes with waitpid().

Background jobs are tracked in a job table so the shell can report status changes and reap zombie processes. Signal handlers forward interrupts to the foreground process group without killing the shell itself.

What I learned

This project made process management concrete. Reading about fork in a textbook is different from debugging a pipeline where stage two never receives input because a file descriptor was left open. The shell is one of the projects that most directly prepared me for thinking about how programs actually run on an OS.
